# 가계부

사기 전에 써도 되는지 알려 주는 통장 쪼개기 가계부예요.

통장을 수입 · 고정지출 · 이벤트 · 저수지 · 저축투자로 나눠 두고, 매달 배분과 지출을 기록하면 이런 걸 알려 줘요.

- **월급통장 하나 + 수입 계획**: 두 사람 월급이 함께 쓰는 월급통장 하나로 들어와요. 사람마다 '누가 · 얼마 · 매달 며칠 · 어느 통장'을 수입 계획으로 적어 두면 그날 수입이 자동으로 기록돼요. 예전처럼 사람마다 수입통장을 두는 가계부도 그대로 써요.
- **월급날마다 배분 · 나머지 전부 보내기**: 월급날마다 정한 금액을 각 통장으로 보내고, 남은 돈은 '나머지 전부 보내기'로 저수지에 모두 보내요(0원 아래로는 보내지 않고, 금액은 그날 기록될 때 정해져요). 예산 화면에서 '21일: 297만 → 생활비(가람) 82.8만 · 이벤트 50만 · 나머지 36.94만 → 저수지'처럼 미리 보여 줘요.
- **사람별 생활비 · 용돈 통장**: 사람마다 생활비 통장과 용돈 통장을 둘 수 있어요. 생활비 예산과 고정비는 통장 주인의 것이고, 홈은 '오늘 내가 써도 되는 돈'을 크게, 다른 사람과 둘이 합친 금액을 작게 보여 줘요. 기록할 때 '누가 썼나요?'(기본 나)를 고르면 그 사람 생활비 통장에서 나가요. 이벤트통장 지출은 함께 쓰는 돈이에요.
- **항목별 생활비 예산**: 식비 · 카페 · 교통 · 쇼핑처럼 항목마다 한 달 예산을 정해요. 매일 쓰는 항목은 '하루에 나눠 쓰기', 가끔 쓰는 항목은 '한 달 한도만'으로 봐요.
- **오늘 써도 되는 돈**: 하루에 나눠 쓰는 항목마다 남은 돈을 남은 날로 나눈 금액의 합이에요. 매일 다시 계산해요. 항목마다 남은 돈도 막대로 보여 줘요.
- **사도 돼?**: 금액과 어디에 쓸지(생활비 항목)를 고르면 그 항목 예산으로 괜찮아요 · 가능하지만 · 비추천 세 단계로 알려 줘요. 경조사 · 여행처럼 이벤트통장으로 살 수도 있어요.
- **이벤트통장 12개월 예측**: 경조사 · 여행 · 명절 일정을 미리 넣어 두면 돈이 모자라는 달을 미리 알려 주고, 대처 방법 두 가지를 제안해요.
- **할부**: TV · 노트북처럼 나눠 내는 돈을 총액(또는 매달 금액)과 개월로 넣으면 결제일마다 자동으로 기록되고, 마지막 회차 뒤에 저절로 끝나요. 'TV 할부 · 16/24회차 · 남은 8회 · 남은 금액 800,000원'처럼 보여 줘요. 도중에 고치거나 미리 갚으면 다음 회차부터만 바뀌고 지난 회차는 그대로예요(저장이 중간에 끊겨도 줄인 회차가 다시 기록되지 않고, 미리 갚은 돈은 맨 마지막에 기록해요). 끝난 할부도 눌러서 지울 수 있어요. 사도 돼?에서 큰 금액은 '12개월 할부면 매달 ○원'과 그 금액이 맞는지도 알려 줘요(여행을 골랐으면 그 여행 예산으로).
- **여행**: 이름 · 떠나는 날 · 돌아오는 날 · 총예산과 항목 예산(항공 · 숙박 · 교통 · 식비 · 투어 · 쇼핑 · 기타)을 넣어요. 여행 예산은 이벤트통장에서 나가요. 몇 달 전에 낸 항공권, 여행 중 식비처럼 날짜가 다른 지출을 기록할 때 여행을 고르면 한 여행으로 모여요(예전 기록이 저수지에서 나갔어도 통장은 그대로 두고 묶어요). 이벤트 화면의 여행 카드와 여행 화면에서 예산 · 쓴 돈 · 남은 돈, 항목마다 막대, 낸 돈 목록을 봐요. 아직 안 쓴 예산은 여행 날짜의 달에 12개월 예측으로 들어가고, 이미 낸 돈은 두 번 빼지 않아요. 지출 하나는 일정과 여행 중 하나에만 묶어요. 사도 돼?에서 여행을 고르면 그 여행의 남은 예산으로 판단해요.
- **돌려받을 돈(청구)**: 이벤트통장이나 생활비에 쓸 돈을 개인 돈으로 냈으면 '개인 돈으로 냈어요'와 낸 사람을 골라요. 언제 돌려주는지(이벤트통장 잔액이 넉넉하면 오늘, 아니면 다음 월급날) 바로 알려 주고, 홈과 이벤트 화면에 사람별로 모아 보여 줘요. 돌려주면 [보냈어요]로 이체를 남겨요. 돌려주기 전까지는 예측에서 정산일에 나갈 돈으로 잡혀요. 돌려준 청구를 고치거나 지우면 돌려준 이체도 함께 바뀌어요.

- **파일에서 가져오기**: 설정의 기록 도우미에서 다른 곳(예: 노션)에서 옮긴 가져오기 파일(JSON, 아래 형식)을 골라요. 표마다 몇 개 · 얼마가 더해지는지, 이름이 같아 합칠 통장 · 카테고리, 돌려받을 돈(사람별)을 먼저 보여 주고 **가져오기**를 눌러야 저장해요. 같은 파일을 다시 가져와도 두 번 생기지 않아요. 구글 시트와 체험 모드 모두 돼요.

## 화면

메뉴는 다섯 칸이에요: **홈 · 내역 · + · 이벤트 · 예산**. 설정은 오른쪽 위(데스크톱은 사이드바 아래)의 내 정보 버튼에서 열어요.

| 메뉴 | 주소 | 하는 일 |
| --- | --- | --- |
| 홈 | `/` | 오늘 내가 써도 되는 돈, 사도 돼?, 돌려받을 돈, 모자라는 달 알림, 자주 쓰는 지출 |
| 내역 | `/history` | 지출 · 이체 · 통장 잔액을 탭으로 바꿔 봐요. 실제 잔액 맞추기 · 이체 기록도 여기서 해요 |
| + | | 지출 기록 · 사도 돼? · 이체 기록 중에서 골라요 |
| 예산 | `/budget` | 돈을 나누는 설정을 한곳에: ① 월급과 배분(수입 계획 · 매달 배분) ② 생활비 항목 ③ 고정비 · 할부. 사람마다 탭으로 나눠 봐요 |
| 계획 | `/plan` | 이벤트통장 일정 · 12개월 예측 · 부족 대처 · 여행(`/plan/trips`) |
| 설정 | `/settings` | 가계부 · 통장 · 멤버 · 공유(초대 링크) · 카테고리 · 자주 쓰는 지출 · 파일에서 가져오기 · 테마 · 로그아웃 |

사람을 묻는 곳(통장 주인 · 수입 계획 · 용돈 받는 사람 · 새 가계부의 버는 사람)은 함께 쓰는 사람을 '이름 · 이메일'로 골라요. 아직 초대하지 않은 사람은 **직접 입력**을 골라 적으면 돼요.

예전 주소(`/expenses` · `/accounts` · `/events` · `/events/trips` · `/members`)는 새 화면으로 넘겨 줘요.

데이터는 내 구글 드라이브의 구글 시트에 저장돼요. 가계부 하나가 스프레드시트 하나예요. 따로 운영하는 서버는 없어요.

자세한 기획은 [PLAN.md](PLAN.md)에 있어요.

- 배포 주소: https://budget-app-mocha-pi.vercel.app

## 가져오기 파일 형식 (budget-import v2)

설정 > 기록 도우미 > 파일에서 가져오기가 읽는 JSON 이에요. 표는 모두 선택이고, 각 행에는 파일 안에서 겹치지 않는 `key`(영문 · 숫자 · `_ . -`, 64자까지)를 둬요. 행끼리는 key 로 가리켜요(예: 지출의 `account` = 통장 key). 금액은 원 단위 정수, 날짜는 `YYYY-MM-DD`, 월은 `YYYY-MM` 이에요.

지금 버전은 2예요. 버전 1 파일도 그대로 가져와요(v1 에는 `incomePlans` · `rules[].kind` 를 쓸 수 없어요). 아래는 v1 칸이고, v2 에서 더한 칸은 그 아래에 있어요.

```jsonc
{
  "format": "budget-import",
  "version": 1,
  "source": "my-export-1",          // 출처 이름. 행 id 가 imp:<source>:<표>:<key> 로 정해져 다시 가져와도 늘지 않아요
  "name": "옮길 가계부",              // 미리보기 제목 (선택)
  "accounts":      [{ "key": "inc-a", "name": "가람 수입통장", "role": "income", "openingBalance": 0, "openingDate": "2026-11-09",
                      "ownerName": "가람", "ownerEmail": null, "salary": 3000000, "salaryDay": 21 },
                   { "key": "event", "name": "이벤트통장", "role": "event", "openingDate": "2026-11-09" },   // 이름이 같은 통장이 있으면 합쳐요
                   { "key": "fixed", "name": "고정지출통장", "role": "fixed", "openingDate": "2026-11-09" }],
  "categories":    [{ "key": "occ", "name": "경조사", "icon": "envelope", "defaultAccountRole": "event", "note": "미리보기에만 보여요" },
                    { "key": "food", "name": "식비", "icon": "dots", "defaultAccountRole": "fixed" }],
  "rules":         [{ "key": "r1", "from": "inc-a", "to": "event", "amount": 300000, "dayOfMonth": 21, "startMonth": "2026-11", "endMonth": null }],
  "fixedExpenses": [{ "key": "rent", "name": "월세", "amount": 500000, "account": "fixed", "kind": "bill", "dayOfMonth": 21,
                      "startMonth": "2026-11", "memo": "관리비 포함" },                       // kind: bill · living(spread daily/monthly, category) · allowance(targetEmail)
                    { "key": "food", "name": "식비", "amount": 400000, "account": "fixed", "kind": "living", "spread": "daily", "category": "food", "startMonth": "2026-11" }],
  "installments":  [{ "key": "tv", "name": "TV 할부", "amount": 60000, "amountKind": "monthly", "months": 9, "firstMonth": "2026-11",
                      "dayOfMonth": 23, "account": "fixed", "category": null }],
  "events":        [{ "key": "wed", "date": "2027-05-16", "name": "결혼식", "amount": 200000, "account": "event", "status": "planned", "repeat": "none" }],
  "trips":         [{ "key": "jeju", "name": "제주 여행", "startDate": "2027-02-20", "endDate": "2027-02-23", "budget": 900000, "items": { "flight": 300000 } }],
  "expenses":      [{ "key": "e1", "date": "2026-10-05", "amount": 70000, "account": "event", "category": "occ", "memo": "선물",
                      "event": null, "trip": null, "tripItem": null,
                      "claim": { "payer": "나래", "status": "pending", "due": null, "settledDate": null } }],
  "transfers":     [{ "key": "t1", "date": "2026-11-21", "kind": "income", "to": "inc-a", "amount": 3000000, "memo": "월급" }]
}
```

- 통장 · 카테고리는 이름(띄어쓰기 무시)이 같은 것이 가계부에 있으면 새로 만들지 않고 합쳐요. 합친 통장은 시작 잔액 · 시작일을 그대로 두고 비어 있는 주인 칸만 채워요
- `salary` 를 주면 시작일 뒤 첫 월급날에 수입 기록 한 건을 남겨요 (그 뒤 달은 앱에서 기록해요)
- 할부는 할부 추가와 같은 규칙이에요: 결제일이 오늘보다 앞선 회차는 이미 낸 것으로 보고 기록하지 않아요. 이미 다 낸 할부는 건너뛰어요
- 청구 `pending` 은 앱 규칙으로 돌려받을 통장(낸 사람이 주인인 수입통장)과 정산일(`due` 를 비우면 4-9 규칙)을 정해요. `settled` 는 돌려준 이체(`claim:<지출id>`, 날짜 = `settledDate` 또는 지출 날짜)도 함께 남겨요. 청구는 이벤트통장 · 고정지출통장 지출만 돼요
- 일정과 여행에 함께 묶인 지출은 여행에만 묶어요. 통장을 안 적은 일정은 이벤트통장으로 가요
- 틀린 칸이 있으면 미리보기 없이 고칠 곳을 알려 줘요. 쓰기는 통장 → 카테고리 → 여행 → 일정 → 매달 배분 → 수입 계획 → 고정 지출 → 지출 → 이체 순서이고 같은 id 는 건너뛰어, 중간에 끊겨도 다시 가져오면 빠진 것만 더해요

### v2 에서 더한 칸

```jsonc
{
  "format": "budget-import",
  "version": 2,
  "source": "couple-1",
  "accounts": [
    { "key": "salary", "name": "월급통장", "role": "income", "openingDate": "2026-11-01" },
    { "key": "liv-a", "name": "생활비(가람)", "role": "fixed", "openingDate": "2026-11-01", "ownerName": "가람" },   // 사람별 생활비 통장
    { "key": "pocket-a", "name": "용돈(가람)", "role": "allowance", "openingDate": "2026-11-01", "ownerName": "가람" }, // 사람별 용돈 통장
    { "key": "res", "name": "저수지통장", "role": "reservoir", "openingDate": "2026-11-01" }
  ],
  "incomePlans": [                                     // 수입 계획: 누가 · 얼마 · 매달 며칠 · 받는 통장
    { "key": "garam", "person": "가람", "email": null, "amount": 2970000, "dayOfMonth": 21, "account": "salary", "startMonth": "2026-11" }
  ],
  "rules": [
    { "key": "a", "from": "salary", "to": "liv-a", "kind": "fixed", "amount": 828000, "dayOfMonth": 21, "startMonth": "2026-11" },
    { "key": "rest21", "from": "salary", "to": "res", "kind": "remainder", "dayOfMonth": 21, "startMonth": "2026-11" }  // 나머지 전부 (amount 없음)
  ],
  "fixedExpenses": [
    { "key": "dues-a", "name": "회비", "amount": 30000, "account": "liv-a", "kind": "bill", "dayOfMonth": 5, "startMonth": "2026-11" },
    { "key": "food-a", "name": "식비", "amount": 300000, "account": "liv-a", "kind": "living", "spread": "daily", "startMonth": "2026-11" }
  ]
}
```

- `incomePlans`: 받는 날마다 수입이 자동으로 기록돼요(`income:<계획id>:<월>`). 같은 월급을 `transfers` 나 `salary` 로 또 넣지 마세요
- `rules[].kind`: `fixed`(기본, `amount` 필요) · `remainder`(그날 정한 금액을 보낸 뒤 남은 돈 전부, `amount` 는 비우거나 0). 같은 통장 · 같은 날 `remainder` 는 하나만
- 사람별 생활비 · 용돈 통장은 통장의 `ownerName` · `ownerEmail` 로, 생활비 예산 · 고정비는 그 통장(`account`)으로 적어요

## 체험 모드

구글 로그인 없이 써 볼 수 있어요. 첫 화면에서 **체험해 보기**를 누르면 돼요.

- 예시 가계부 '민지·준호 가계부'가 열려요. 함께 쓰는 월급통장 하나에 민지 월급(21일 3,200,000원) · 준호 월급(25일 2,800,000원) 수입 계획이 있고, 21일에는 생활비(민지) · 생활비(준호) · 이벤트, 25일에는 용돈(민지) · 용돈(준호) · 저축투자로 정한 금액을 보낸 뒤 나머지는 모두 저수지로 가요. 사람마다 생활비 통장(고정비 · 항목 예산)과 용돈 통장이 있고, 홈은 민지 기준 '오늘 내가 써도 되는 돈'으로 열려요. 그 밖에 사람마다 생활비 항목 예산 7개, 일정, 지출, 개인 돈으로 내고 돌려받을 돈(오늘 돌려줄 것 · 다음 월급날에 돌려줄 것 · 이미 돌려준 것), 16회차까지 낸 TV 할부(24개월), 숙소 예약금 · 항공권을 미리 낸 석 달 뒤 제주 여행(예산 900,000원)이 미리 들어 있어요.
- 모든 화면과 기능을 그대로 써 볼 수 있어요. 새 가계부(공용 · 개인)도 만들 수 있어요.
- 데이터는 **이 브라우저에만** 저장돼요. 다른 기기나 다른 사람과는 함께 쓸 수 없어요.
- 브라우저 사이트 데이터를 지우면 체험 가계부도 함께 지워져요. 사생활 보호 창에서는 창을 닫을 때 사라져요.
- 구글 설정을 하지 않은 상태에서는 **구글로 시작하기** 버튼이 꺼지고 체험 모드만 쓸 수 있어요.

## 함께 쓰기 (공유)

공용 가계부는 구글 시트 공유로 함께 써요. 앱은 `drive.file` 권한만 쓰기 때문에, 남이 공유한 시트는 **구글 파일 선택 창에서 한 번 골라야** 읽을 수 있어요.

1. **설정** → **멤버 · 공유**에서 상대의 구글 이메일로 **초대하기**를 눌러요. 시트가 그 이메일로 공유돼요(편집 권한).
2. 같은 화면의 **초대 링크**에서 **링크 복사**를 눌러 상대에게 보내요. 링크는 `https://<주소>/start?open=<스프레드시트 id>` 모양이에요.
3. 상대가 링크를 열면 '가계부에 초대받았어요'가 보이고, 구글로 로그인하면 그 시트만 골라 둔 파일 선택 창이 떠요. **선택**만 누르면 가계부가 열리고 최근 목록에 남아요. 다음부터는 링크 없이 열려요.
   - 이미 읽을 수 있는 시트(내가 만든 시트나 전에 고른 시트)면 선택 창 없이 바로 열려요.
   - 선택 창을 닫으면 **다시 열기**로 다시 띄울 수 있어요.
4. 링크가 없어도 돼요. 구글로 처음 로그인해 최근 가계부가 없으면 시작 화면 맨 위에 **공유받은 가계부가 있나요?**가 보여요. **공유받은 가계부 열기**를 눌러 그 시트를 고르면 돼요.

체험 모드 가계부는 이 브라우저에만 저장돼서 링크로 공유할 수 없어요. 링크 복사를 누르면 구글 가계부에서만 된다고 알려 줘요.

## 기술 구성

| 항목 | 사용한 것 |
| --- | --- |
| 프레임워크 | Next.js 16 (App Router), React 19, TypeScript (strict) |
| 배포 | Vercel. 화면은 모두 정적 페이지예요. 서버는 로그인용 작은 API(`/api/auth/*`, Vercel 무료 함수) 하나뿐이고 가계부 데이터는 다루지 않아요 |
| 데이터 저장 | 구글 시트 (Sheets API v4 · Drive API v3를 브라우저에서 직접 호출). 체험 모드는 브라우저 저장(localStorage) |
| 로그인 | 구글 인증 코드 흐름 + 갱신 토큰. 갱신 토큰은 암호화한 httpOnly 쿠키에만 두고, 브라우저는 1시간짜리 액세스 토큰만 받아요. 서버 설정이 없으면 예전처럼 Google Identity Services 팝업으로 로그인해요 |
| 공유받은 가계부 열기 | Google Picker (구글 파일 선택 창) |
| 화면 | 웹 공통 디자인 시스템 토큰 + 자체 UI 키트. 글꼴 Pretendard, 선 아이콘(SVG). 움직임은 디자인 시스템 motion.md 기준(CSS 는 components.css, 스크립트가 필요한 숫자 세기·목록 추가/삭제·창 닫힘은 src/ui/motion.ts). '움직임 줄이기' 설정을 따라요 |
| 테스트 | Vitest 3, Testing Library, jsdom |
| 앱 설치 | PWA (홈 화면에 추가). 오프라인 입력은 지원하지 않아요 |

구조는 네 층으로 나뉘어 있어요.

```
화면 (src/app)
  └─ 상태 (src/state)        로그인 · 가계부 선택 · 데이터 · 계산값 · 행동
       ├─ 계산 (src/domain)   항목별 생활비 · 이벤트 예측 · "사도 돼?" 판단 · 청구 정산일 · 할부 회차 · 여행 예산 · 가져오기 파일 확인 (순수 함수)
       └─ 저장 (src/storage)  구글 시트 / 브라우저 저장 (같은 인터페이스)
            └─ 구글 (src/google)  로그인 · 토큰 · 파일 선택 창
                 └─ 로그인 서버 (src/app/api/auth → src/server/auth)  갱신 토큰 쿠키 · 새 액세스 토큰
```

화면은 상태 층만 불러요. 저장 위치를 바꿔도 화면 코드는 그대로예요.

## 로컬에서 실행하기

Node.js 22 이상이 필요해요.

```bash
npm ci                         # package-lock.json 그대로 설치
cp .env.example .env.local     # 구글 환경 변수 파일 만들기 (체험 모드만 쓸 거면 비워 둬도 돼요)
npm run dev                    # http://localhost:3000
```

`.env.local`에는 아래 값을 넣어요. 값을 만드는 방법은 [구글 클라우드 설정](#구글-클라우드-설정)과 [로그인 서버 켜기](#로그인-서버-켜기-매번-구글-확인-없이)에 있어요.

```bash
NEXT_PUBLIC_GOOGLE_CLIENT_ID=123456789012-abcdefg.apps.googleusercontent.com
NEXT_PUBLIC_GOOGLE_API_KEY=AIza...
NEXT_PUBLIC_GOOGLE_APP_ID=123456789012
# 로그인 서버 (비워 두면 예전처럼 팝업으로 로그인해요)
GOOGLE_CLIENT_SECRET=GOCSPX-...
AUTH_COOKIE_SECRET=openssl rand -base64 32 로 만든 값
```

- `.env.local`을 고친 뒤에는 `npm run dev`를 껐다 다시 켜야 반영돼요.
- `.env.local`은 git에 올라가지 않아요 (`.gitignore`).
- `NEXT_PUBLIC_`으로 시작하는 세 값은 브라우저로 내려가는 공개 값이에요. 보안은 구글 클라우드의 주소 제한과 테스트 사용자 목록이 지켜요.
- `GOOGLE_CLIENT_SECRET`과 `AUTH_COOKIE_SECRET`은 **서버에만 있는 비밀 값**이에요. 앞에 `NEXT_PUBLIC_`을 붙이지 마세요(붙이면 브라우저로 새어 나가요). 채팅 · 이슈 · 커밋에 붙여 넣지 마세요.

## 구글 클라우드 설정

구글 로그인과 구글 시트 저장을 쓰려면 구글 클라우드에서 값 세 개를 만들어야 해요. 개발을 몰라도 아래 순서대로 하면 돼요. 30분쯤 걸려요.

> 구글 클라우드 화면은 자주 바뀌어요. 메뉴 이름이 조금 다르면 비슷한 이름을 찾아 주세요. 'OAuth 동의 화면'은 새 화면에서 **Google 인증 플랫폼**(Google Auth Platform)으로 바뀌었어요.

### 1. 프로젝트 만들기

1. https://console.cloud.google.com 에 구글 계정으로 들어가요.
2. 맨 위 프로젝트 선택 상자를 누르고 **새 프로젝트**를 눌러요.
3. 프로젝트 이름에 `budget-app`처럼 알아보기 쉬운 이름을 넣고 **만들기**를 눌러요.
4. 만들어지면 맨 위 프로젝트 선택 상자에서 방금 만든 프로젝트를 골라요. 아래 단계는 모두 이 프로젝트 안에서 해요.

### 2. API 세 개 켜기

1. 왼쪽 메뉴(☰) → **API 및 서비스** → **라이브러리**로 가요.
2. 검색창에 아래 이름을 하나씩 넣고, 결과를 눌러 **사용**(Enable)을 눌러요.
   - **Google Sheets API**: 가계부 시트를 읽고 써요.
   - **Google Drive API**: 멤버를 초대할 때 시트를 공유해요.
   - **Google Picker API**: 공유받은 가계부를 고르는 파일 선택 창이에요.
3. **API 및 서비스** → **사용 설정된 API 및 서비스**에 세 개가 모두 보이면 돼요.

### 3. OAuth 동의 화면 (Google 인증 플랫폼)

로그인할 때 보이는 동의 창을 설정해요.

1. 왼쪽 메뉴 → **API 및 서비스** → **OAuth 동의 화면**으로 가요. 새 화면이면 **시작하기**를 눌러요.
2. **앱 정보**
   - 앱 이름: `가계부`
   - 사용자 지원 이메일: 내 이메일
3. **대상**(User Type): **외부**(External)를 골라요.
4. **연락처 정보**: 내 이메일을 넣고, 정책에 동의한 뒤 **만들기**를 눌러요.
5. **범위 추가** (새 화면에서는 왼쪽 **데이터 액세스** → **범위 추가 또는 삭제**)
   - 아래 네 개를 체크해요. 목록에 안 보이면 맨 아래 '직접 범위 추가' 칸에 그대로 붙여 넣어요.
     - `openid`
     - `.../auth/userinfo.email` (email)
     - `.../auth/userinfo.profile` (profile)
     - `https://www.googleapis.com/auth/drive.file`
   - **업데이트** → **저장**을 눌러요.
   - `drive.file`은 이 앱이 만든 파일과 사용자가 파일 선택 창에서 고른 파일만 볼 수 있는 권한이에요. 드라이브의 다른 파일은 볼 수 없어요.
6. **테스트 사용자** (새 화면에서는 왼쪽 **대상** → **테스트 사용자**)
   - **사용자 추가**를 누르고 가계부를 쓸 사람의 구글 이메일을 모두 넣어요. 공용 가계부를 함께 쓸 가족도 넣어야 해요.
   - 최대 100명까지 넣을 수 있어요. 목록에 없는 사람은 로그인할 수 없어요.
7. **게시 상태**가 **테스트 중**(Testing)인지 확인해요. 처음에는 테스트 중으로 시작해요. 테스트 중이면 구글 심사가 필요 없지만 로그인 서버의 갱신 토큰이 7일마다 끝나요. 7일 제한을 없애는 게시 방법은 [로그인 서버 켜기 4단계](#4-테스트-중이면-7일마다-다시-로그인해요)에 있어요.

### 4. OAuth 클라이언트 ID 만들기

1. 왼쪽 메뉴 → **API 및 서비스** → **사용자 인증 정보** → **사용자 인증 정보 만들기** → **OAuth 클라이언트 ID**를 눌러요. (새 화면에서는 **클라이언트** → **클라이언트 만들기**)
2. 애플리케이션 유형: **웹 애플리케이션**
3. 이름: `가계부 웹` 처럼 아무거나 넣어요.
4. **승인된 자바스크립트 원본**에 아래 두 주소를 하나씩 추가해요.
   - `http://localhost:3000`
   - `https://budget-app-mocha-pi.vercel.app`
   - 주소 끝에 `/`를 붙이지 않아요. 경로도 붙이지 않아요.
5. **승인된 리디렉션 URI**에 아래 두 주소를 추가해요. 로그인 서버가 구글에서 돌아오는 주소예요.
   - `https://budget-app-mocha-pi.vercel.app/api/auth/callback`
   - `http://localhost:3000/api/auth/callback`
6. **만들기**를 누르면 클라이언트 ID가 보여요. `123456789012-xxxx.apps.googleusercontent.com` 모양이에요. 이 값을 복사해 두세요. → `NEXT_PUBLIC_GOOGLE_CLIENT_ID`
   - 같이 보이는 **클라이언트 보안 비밀번호**는 로그인 서버의 `GOOGLE_CLIENT_SECRET`이에요. [로그인 서버 켜기](#로그인-서버-켜기-매번-구글-확인-없이)에서 Vercel에만 넣어요.
7. 원본을 바꾸면 반영까지 5분에서 몇 시간이 걸릴 수 있어요.

**미리보기(Preview) 배포 주소에 대해**

- Vercel은 브랜치와 PR마다 미리보기 주소를 따로 만들어요.
  - 배포마다 바뀌는 주소: `budget-app-<임의 글자>-<팀 이름>.vercel.app`
  - 브랜치마다 고정된 주소: `budget-app-git-<브랜치 이름>-<팀 이름>.vercel.app`
- 구글은 원본에 `*` 같은 와일드카드를 받지 않아요. 그래서 미리보기 주소는 하나씩 직접 넣어야 해요.
- 미리보기에서 구글 로그인까지 확인해야 할 때만 그 브랜치의 고정 주소를 원본에 추가해요. 아래 5단계의 API 키 웹사이트 제한에도 같은 주소를 넣고, 리디렉션 URI에도 `https://<그 주소>/api/auth/callback`을 넣어요.
- 그 밖의 미리보기는 **체험 모드**로 확인하면 돼요. 구글 설정 없이 모든 화면을 볼 수 있어요.

### 5. API 키 만들기 (파일 선택 창용)

1. **API 및 서비스** → **사용자 인증 정보** → **사용자 인증 정보 만들기** → **API 키**를 눌러요.
2. 키가 만들어지면 **키 수정**(또는 키 이름)을 눌러 제한을 걸어요.
3. **애플리케이션 제한사항**: **웹사이트**(HTTP 리퍼러)를 고르고 아래 두 개를 추가해요.
   - `http://localhost:3000/*`
   - `https://budget-app-mocha-pi.vercel.app/*`
   - `*.vercel.app/*`처럼 넓게 넣지 마세요. 다른 사람의 Vercel 사이트도 이 키를 쓸 수 있게 돼요.
4. **API 제한사항**: **키 제한**을 고르고 **Google Picker API** 하나만 체크해요.
5. **저장**을 누르고 키 값(`AIza...`)을 복사해 두세요. → `NEXT_PUBLIC_GOOGLE_API_KEY`

### 6. 프로젝트 번호 확인 (앱 ID)

1. 왼쪽 메뉴 → **IAM 및 관리자** → **설정**으로 가요. (또는 홈 대시보드의 **프로젝트 정보** 카드)
2. **프로젝트 번호**(12자리쯤 되는 숫자)를 복사해요. → `NEXT_PUBLIC_GOOGLE_APP_ID`
   - 글자로 된 **프로젝트 ID**와 다른 값이에요. 숫자인 **프로젝트 번호**를 써요.
   - 클라이언트 ID 맨 앞 숫자와 같아요. 이 값을 비워 두면 앱이 클라이언트 ID 앞 숫자를 대신 써요.

### 7. 값 세 개 넣기

**로컬** — `.env.local`

```bash
NEXT_PUBLIC_GOOGLE_CLIENT_ID=4단계의 클라이언트 ID
NEXT_PUBLIC_GOOGLE_API_KEY=5단계의 API 키
NEXT_PUBLIC_GOOGLE_APP_ID=6단계의 프로젝트 번호
```

넣은 뒤 `npm run dev`를 다시 켜요.

**Vercel** — 프로젝트 설정

1. https://vercel.com 에서 이 프로젝트를 열고 **Settings** → **Environment Variables**로 가요.
2. 세 값을 하나씩 추가해요.
   - **Key**: `NEXT_PUBLIC_GOOGLE_CLIENT_ID` (나머지 둘도 같은 방법으로)
   - **Value**: 복사해 둔 값
   - **Environments**: **Production**과 **Preview**를 둘 다 체크해요.
3. **Save**를 눌러요.

### 8. 다시 배포하기

`NEXT_PUBLIC_`으로 시작하는 값은 빌드할 때 앱 안에 들어가요. 값을 넣거나 바꾼 뒤에는 꼭 다시 배포해야 해요.

1. Vercel 프로젝트 → **Deployments**로 가요.
2. 맨 위 Production 배포 오른쪽 **⋯** → **Redeploy**를 눌러요.
3. 배포가 끝나면 https://budget-app-mocha-pi.vercel.app 에서 **구글로 시작하기** 버튼이 켜졌는지 확인해요.

### 9. 처음 로그인하기

1. **구글로 시작하기**를 누르고 테스트 사용자로 넣은 계정을 골라요.
2. 'Google에서 확인하지 않은 앱' 안내가 나오면 **계속**을 눌러요. 테스트 중인 앱이라 나오는 안내예요.
3. 권한 화면에서 **구글 드라이브 파일** 항목을 꼭 체크하고 **계속**을 눌러요. 체크하지 않으면 가계부를 쓸 수 없어요.
4. **새 가계부 만들기**를 누르면 내 구글 드라이브에 시트가 만들어져요.
5. 함께 쓸 사람은 **설정** → **멤버 · 공유**에서 이메일로 초대하고 **링크 복사**로 초대 링크를 보내요. 초대받은 사람은 링크를 열어 로그인한 뒤 **선택**만 누르면 돼요(링크 없이 **공유받은 가계부 열기**로 골라도 돼요). 초대받은 사람도 3단계의 테스트 사용자여야 해요. 자세한 흐름은 [함께 쓰기](#함께-쓰기-공유)에 있어요.

## 로그인 서버 켜기 (매번 구글 확인 없이)

예전에는 앱을 열 때마다 구글 확인 창이 잠깐 뜨거나 막혔어요. 브라우저가 1시간짜리 토큰만 받았기 때문이에요. 로그인 서버를 켜면 처음 한 번만 구글에서 허용하고, 그다음부터는 앱을 열자마자 바로 써요. 가계부 데이터는 그대로 구글 시트에 있고, 서버에는 데이터베이스가 없어요. 서버는 '다시 로그인 없이 새 토큰 받기'만 해요.

설정하지 않아도 앱은 돌아가요. 그때는 예전처럼 팝업으로 로그인해요.

### 1. 구글 클라우드에서 주소 넣고 비밀번호 복사하기

1. https://console.cloud.google.com → 이 프로젝트 → **Google 인증 플랫폼**(또는 **API 및 서비스**) → **클라이언트**로 가요.
2. **가계부 웹**을 눌러요.
3. **승인된 리디렉션 URI**에서 **URI 추가**를 눌러 아래 두 주소를 넣어요. 끝에 `/`를 붙이지 않아요.
   - `https://budget-app-mocha-pi.vercel.app/api/auth/callback`
   - `http://localhost:3000/api/auth/callback`
4. **저장**을 눌러요. 반영까지 몇 분 걸릴 수 있어요.
5. 같은 화면 오른쪽(또는 아래)의 **클라이언트 보안 비밀번호**(`GOCSPX-`로 시작)를 복사해요. 안 보이면 **보안 비밀 추가**로 새로 만들어요. 이 값은 아래 2단계에만 붙여 넣어요.

### 2. Vercel에 비밀 값 두 개 넣기

1. https://vercel.com → **budget-app** → **Settings** → **Environment Variables**로 가요.
2. 첫 번째 값
   - **Key**: `GOOGLE_CLIENT_SECRET`
   - **Value**: 1단계에서 복사한 클라이언트 보안 비밀번호
   - **Sensitive**를 켜요. **Environments**는 **Production**과 **Preview**를 체크해요.
3. 두 번째 값
   - **Key**: `AUTH_COOKIE_SECRET`
   - **Value**: 로그인 쿠키를 암호화하는 열쇠예요. 아무도 모르는 32바이트 무작위 값이면 돼요. 터미널에서 아래 한 줄로 만들어요. 어시스턴트에게 대신 넣어 달라고 해도 돼요.
     ```bash
     openssl rand -base64 32
     ```
   - **Sensitive**를 켜고 **Production**과 **Preview**를 체크해요.
   - 이 값을 바꾸면 모든 사람이 한 번 다시 로그인해야 해요.
4. **Save**를 눌러요.

로컬에서도 쓰려면 `.env.local`에 같은 두 줄을 넣고 `npm run dev`를 다시 켜요. 로컬용 `AUTH_COOKIE_SECRET`은 따로 새로 만들어도 돼요.

### 3. 다시 배포하기

1. Vercel 프로젝트 → **Deployments** → 맨 위 Production 배포 오른쪽 **⋯** → **Redeploy**를 눌러요.
2. 끝나면 https://budget-app-mocha-pi.vercel.app/api/auth/status 를 열어 `{"serverLogin":true}`가 보이는지 확인해요. `false`면 두 값의 이름 · 환경(Production)을 다시 확인해요.
3. 앱에서 **구글로 시작하기**를 눌러요. 이번에는 팝업 대신 구글 화면으로 넘어갔다가 돌아와요. 처음 한 번은 권한 화면이 다시 나와요(**구글 드라이브 파일** 체크). 그다음부터는 앱을 열면 바로 열려요.

### 4. 테스트 중이면 7일마다 다시 로그인해요

- 구글 OAuth 안내 기준으로 **게시 상태가 '테스트 중'인 앱**이 이름 · 이메일 · 프로필 말고 다른 권한(이 앱은 `drive.file`)을 받으면 갱신 토큰이 **7일 뒤 끝나요**. 그러면 앱이 '로그인이 만료됐어요. 다시 로그인해 주세요'를 보여 주고, 구글로 시작하기를 한 번 누르면 이어서 써요(최근 가계부는 그대로 남아요).
- 7일 제한을 없애려면 앱을 **프로덕션으로 게시**해요.
  1. **Google 인증 플랫폼** → **대상**(Audience) → **앱 게시**(Publish app) → **확인**.
  2. 이 앱이 쓰는 권한(`openid` · `email` · `profile` · `drive.file`)은 구글이 '민감하지 않은 권한'으로 분류하는 것으로 알고 있어요. 그래서 보통은 구글 심사 없이 바로 게시돼요. 다만 구글 정책은 자주 바뀌니, 게시할 때 화면에 **인증 필요**(Verification required)가 뜨는지 꼭 확인해 주세요. 앱 이름 · 로고를 동의 화면에 보이게 하려면 별도의 브랜드 확인을 요청할 수 있어요.
  3. 게시하면 테스트 사용자 목록 제한이 없어져 **구글 계정이 있으면 누구나 로그인할 수 있어요**. 그래도 남의 가계부는 열 수 없어요(`drive.file`이라 내가 만들었거나 공유받아 고른 시트만 보여요).
  4. 게시 전에 받은 갱신 토큰은 그대로 7일 뒤 끝날 수 있어요. 게시한 뒤 한 번 다시 로그인하면 돼요.
- 프로덕션이어도 6개월 동안 쓰지 않거나, 구글 계정 비밀번호를 바꾸거나, 구글 계정 설정에서 앱 권한을 지우면 다시 로그인해야 해요.

### 로그아웃

- **설정 → 계정 → 로그아웃**: 이 기기의 로그인 쿠키와 토큰만 지워요.
- **모든 기기에서 로그아웃**: 구글에 이 앱의 권한을 거둬 달라고 보내요. 다른 기기도 다시 로그인해야 해요. 가계부 시트는 지워지지 않아요.

### 잘 안 될 때

| 보이는 것 | 확인할 것 |
| --- | --- |
| 버튼이 꺼져 있고 '구글 로그인이 아직 설정되지 않았어요' | 클라이언트 ID가 비어 있어요. 로컬은 `npm run dev` 재시작, Vercel은 다시 배포했는지 확인해요 |
| 구글 창에 `invalid_client` | 클라이언트 ID를 잘못 붙여 넣었어요. 앞뒤 빈칸까지 확인해요 |
| 구글 창에 `origin_mismatch` | 지금 주소가 4단계 승인된 자바스크립트 원본에 없어요. 넣었다면 몇 분 뒤 다시 해 봐요 |
| 구글 창에 `redirect_uri_mismatch` | `https://<지금 주소>/api/auth/callback`이 승인된 리디렉션 URI에 없어요. [로그인 서버 켜기](#로그인-서버-켜기-매번-구글-확인-없이) 1단계를 확인해요 |
| '로그인이 만료됐어요. 다시 로그인해 주세요' | 갱신 토큰이 끝났어요(테스트 중인 앱은 7일). 구글로 시작하기를 누르면 돼요. 자주 나오면 앱을 프로덕션으로 게시해요 |
| '구글 로그인을 마치지 못했어요' | Vercel의 `GOOGLE_CLIENT_SECRET`이 클라이언트 보안 비밀번호와 같은지 확인해요 |
| '로그인 확인 시간이 지났어요' | 구글 화면에서 10분 넘게 머물렀거나 쿠키가 막혀 있어요. 다시 눌러요 |
| 구글 창에 `403: access_denied` | 로그인한 계정이 3단계 테스트 사용자 목록에 없어요 |
| '구글 드라이브 권한을 허용해야 쓸 수 있어요' | 권한 화면에서 드라이브 항목 체크를 빼먹었어요. 다시 로그인해 체크해요 |
| '로그인 창이 차단됐어요' | 로그인 서버가 꺼져 있어 팝업으로 로그인하는 중이에요. 팝업을 허용하거나 [로그인 서버](#로그인-서버-켜기-매번-구글-확인-없이)를 켜요 |
| **구글 다시 연결** 버튼이 보여요 | 로그인한 지 오래돼서 연결이 끊겼어요. 버튼을 누르면 같은 계정으로 다시 연결돼요 |
| 파일 선택 창이 열리지 않거나 오류가 나요 | Picker API를 켰는지, API 키의 웹사이트 제한에 지금 주소가 있는지, API 제한에 Picker API가 있는지 확인해요 |
| '이 가계부에 접근할 권한이 없어요' | Sheets API · Drive API를 켰는지 확인해요. 공유받은 가계부라면 만든 사람이 나를 초대했는지 확인하고, **공유받은 가계부 열기**로 한 번 골라야 해요 |
| '이 파일은 가계부로 열 수 없어요' | 이 앱에서 만든 가계부 시트가 아니에요 |
| 초대 링크를 열었는데 '이 가계부를 열 권한이 없어요' | 초대받은 구글 계정으로 로그인했는지 확인해요. 다른 계정이면 로그아웃하고 초대받은 계정으로 다시 열어요 |

## Vercel 배포 설정

- GitHub 저장소 **Settings** → **General** → **Default branch**를 `main`으로 둬요.
- Vercel 프로젝트 **Settings** → **Git**(새 화면에서는 **Environments** → **Production** → **Branch Tracking**)에서 **Production Branch**를 `main`으로 둬요.
- `main`에 올라가면 Production(https://budget-app-mocha-pi.vercel.app)으로 배포되고, 다른 브랜치와 PR은 Preview로 배포돼요.
- 환경 변수는 Production과 Preview 둘 다에 넣어요. 바꾼 뒤에는 다시 배포해요.
- 이름과 쓰임: `NEXT_PUBLIC_GOOGLE_CLIENT_ID` · `NEXT_PUBLIC_GOOGLE_API_KEY` · `NEXT_PUBLIC_GOOGLE_APP_ID`(공개), `GOOGLE_CLIENT_SECRET` · `AUTH_COOKIE_SECRET`(비밀, Sensitive).
- `/api/auth/*`만 서버 함수로 돌고 나머지 화면은 정적 페이지예요. 무료(Hobby) 요금제로 충분해요.

## 알려진 한계

- 실시간 동기화는 하지 않아요. 다른 사람이 쓴 기록은 앱을 열거나 새로고침할 때 보여요.
- 오프라인에서는 기록할 수 없어요.
- 로그인 서버가 켜져 있으면 액세스 토큰(1시간)은 만료 5분 전에 저절로 새로 받아요. 테스트 중인 앱은 7일마다 다시 로그인해야 해요.
- 로그인 서버가 꺼져 있으면(팝업 로그인) 1시간쯤 뒤 조용히 다시 받지 못할 때 **구글 다시 연결** 버튼을 눌러야 해요.
- 액세스 토큰은 빠르게 다시 열려고 만료(1시간)까지 브라우저 저장소에 둬요. 갱신 토큰은 브라우저 스크립트가 읽을 수 없는 쿠키에만 있어요.
- 일정 완료처럼 여러 탭에 나눠 쓰는 작업은 한 번에 묶이지 않아요. 중간에 실패하면 앱이 저장된 데이터를 다시 읽어 와요.
- 개인 가계부와 공용 가계부의 연결은 개인 가계부를 만들 때만 정할 수 있어요.
